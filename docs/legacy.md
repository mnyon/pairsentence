# 间 · PairSentence

## 思源插件第一版

插件只使用当前工作空间，无需配置地址或 Token。构建命令 `npm run build:plugin`；将 `dist/pairsentence` 目录复制到思源工作空间 `data/plugins/`，在插件集市的已下载列表启用，再点击顶栏「间」。标准插件包为 `dist/package.zip`。

图谱和配色、动画、专注偏好保存在 `data/storage/petal/pairsentence/`，随思源工作空间数据同步。换设备前先在原设备完成同步，再在新设备完成同步后打开插件；以单人、同一时间一个设备使用为前提。插件显示已保存仅表示当前工作空间已保存，不代表云端同步完成。

支持从旧油猴版或独立版导入 JSON 备份；插件不再提供跨实例来源。旧备份中不属于当前工作空间的块，会在确认缺失后断开关联，历史思考仍保留。详细安装、同步和发布准备见 [插件说明](plugin/README.zh-CN.md)。目前为本地安装候选包，尚未上架集市；需在真实思源桌面端、手机端及两设备同步中完成验收。

以下保留旧版分发说明。

一个连接本机思源笔记的交互原型。推荐分发独立 HTML 文件，使用者无需安装 Node.js 或任何依赖。

## 油猴版：以 Bilibili 为试用入口

0.4.0 支持多个本机思源来源：设置中点击“添加思源来源”，分别输入地址与 Token 后保存。当前第二实例可使用 `http://127.0.0.1:3684`。旧单来源配置自动迁移，图谱存储键、块 ID、关联及思考都不重置；来源可以交叉配对，按块 ID 去重。相同 ID 有不同正文时以配置顺序靠前的来源为准，不视为两段独立内容。

每个来源均衡抽样最多 80 段。0.5.0 起，即使全部来源离线，也可用已保存正文比较和建立关联；卡片标记“上次同步快照”。无法充分核实缺失时保留旧段落，不再阻止判断。多来源确认删除采用保守规则，存在离线或断开来源时延后断开缺失节点，以保护来源不明的旧数据。修改实例端口时编辑原来源地址。0.5.1 起所有段落均使用 `siyuan://blocks/ID` 原生协议跳转，不再从 Bilibili 访问来源 HTTP 页面，避免思源“跨站请求”限制。多实例的接收窗口由思源桌面端决定，协议本身未指定来源端口，不能保证定位到指定工作空间。Token 只存在独立连接配置，不写入段落或图谱导出。

每行来源有“测试连接”和独立状态（未检测 / 检测中 / 已连接 / 连接失败）。保存配置后自动测试，并保留设置画面展示结果；离线配置仍允许保存。断开 / 清理入口显示影响数量并要求明确选择：断开保留全部数据，或断开并清理独有段落及相关关系与思考。共享段落、无来源的旧段落保留。断开状态持久化，可重新勾选启用；清理不可撤销，应先导出备份。操作先保存断开配置，再原子提交图谱清理，图谱保存失败时旧数据保留、可重试。暂停按钮已移除；收起油猴工具仍保留当前阅读与输入。

分发文件：`dist/PairSentence.user.js`。安装 Tampermonkey 后，在其管理面板选择“添加新脚本”，用这个文件的完整内容替换默认内容并保存。开发服务运行时也可访问 http://127.0.0.1:4173/PairSentence.user.js 触发扩展安装；若浏览器只显示文本，仍可复制到扩展编辑器。Chrome / Edge 若扩展提示需要启用“允许用户脚本”或开发者模式，按扩展指引设置。

1. 打开或刷新任意 HTTPS Bilibili 页面（首页、视频页、空间页均匹配，子框架不运行）。
2. 右下角“间”是唯一常驻入口，点击才初始化工具、读取存储和查询思源；也可以从油猴菜单打开。

   0.5.2 起入口为半透明的窄侧边标签：按住拖动，松开后吸附到最近的左/右边缘；拖动超过阈值不会误触打开。左右侧与垂直位置使用 GM 持久化，刷新后恢复，窗口缩放时保持在可见范围内。鼠标、触控和键盘点击均可使用。
3. 首次在设置填写思源地址和 API Token。请求由 `GM.xmlHttpRequest` 发往本机，不依赖 Bilibili 的跨域规则；若扩展询问本机连接权限，允许即可。
4. 工具覆盖显示思考空间；右上角 × 或关闭所有弹窗后按 Escape 收起。未提交输入会保留，收起后停止自动查询。不会自动暂停 Bilibili 视频。
5. 图谱和配置保存在脚本的 `GM.getValue/setValue` 存储，不是 Bilibili 的 localStorage。已有 HTML / 开发服务版图谱需导出 JSON，再在油猴版导入；脚本卸载前也请备份。仍建议只在一个标签页打开工具进行操作，尚未实现跨标签页写入协调。

Bilibili 只是熟悉且经常访问的启动位置，不参与算法或存储。采用按需打开，避免每次浏览视频都被拉入笔记流程。以后换入口只需调整生成器的 `@match`；不必修改领域或应用层。

界面挂载到 closed Shadow DOM 中隔离宿主样式，视图通过限定作用域的 document 访问。GM 请求、图谱存储和连接 Token 留在脚本闭包中，不挂载到网页全局对象；这不意味着 Shadow DOM 本身是一道安全隔离墙。

维护源文件仍按领域规则、应用用例、连接/存储适配、界面/动效分离，新增 `userscript-shell.js` 专管入口和宿主生命周期。`node build.mjs` 同时生成 HTML 和油猴两个单文件；脚本顶部有文件导航、各源文件段落有稳定标记，无需额外依赖。不要直接修改生成文件；从源文件重新构建以防两种分发形态不同步。

## 点击即用（推荐）

将 `dist/PairSentence.html` 发给使用者，双击即可在现代 Chrome / Edge 中打开。保持思源运行，首次在连接设置填写本机地址和 API Token（思源 → 设置 → 关于）。若浏览器询问本地网络访问权限，允许访问。已实际验证 file:// 页面直接查询本机思源成功；其他浏览器或受管理的网络策略可能限制直连。

独立文件内含全部样式、界面及算法，没有外部字体、CDN、运行时、安装器或 Node 服务，也不包含你的 Token 和笔记。浏览器 IndexedDB 保存图谱及连接配置；仅请求本机思源。换浏览器、移动/重命名文件、清理浏览器数据前请导出 JSON，之后用设置中的“导入备份”恢复。旧服务版数据可在旧页面导出后导入单文件版，不会自动跨存储迁移。图谱备份不含连接 Token。

后续维护只编辑现有源文件，运行 `npm run build` 更新单文件；构建只用 Node 自带能力，不需要安装构建工具。也可在开发页面右上角“连接与备份”直接下载最新独立文件。更新文件前先导出备份，再替换 HTML 即可。

## 动效和专注

- 卡片上方切换“共振 / 星火 / 生长 / 静谧”。切换时自动预览，也可单独点击预览，不会修改图谱。
- 建立关联播放约一秒反馈；暂未关联和跳过使用短暂退场。等待保存成功后才播放动画并切换下一组；失败保留片段、输入和计数，允许重试。支持系统“减少动态效果”。
- 左上角菜单收起整个侧栏，扩大阅读空间；再次点击恢复。专注状态和动画选择会被记住，收起侧栏后仍可从顶部切换图谱。

## 开发服务（可选）

维护者使用 Node.js 22 或更新版本运行：

```powershell
npm start
```

打开 http://127.0.0.1:4173 。默认从 `sample.js` 读取思源地址和令牌；也可以通过 `SIYUAN_URL`、`SIYUAN_TOKEN` 环境变量覆盖。令牌仅供本机服务使用，不发送给浏览器。保持思源运行。

## 交互

- 随机打捞 160 个非空段落（正文超过 15 字符）。比对两个片段，建立关联，可选填一句思考。
- “暂未发现关联”会累计孤立片段的失败次数；3 次后休息 24 小时。“先跳过”不累计。
- 配对策略：20% 尝试不同连通分量之间的桥接，35% 尝试孤立片段接入已有分量，45% 探索两个孤立片段。无候选时回退其他类别。正常候选池回避最近 6–12 轮片段，并记住最近 18 组组合；候选不足时先放宽片段回避，再放宽组合记忆。偏好未读和较少出现的片段，不会推荐已处于同一分量的片段。这段近期记忆属于当前工具会话，完整判断历史仍持久化。
- 同步不再重建正在阅读的卡片；有正文更新时局部替换文字，保留卡片和滚动位置。
- 配色可切换青苔、暖砂、雾蓝、夜读，偏好会保存；油猴版偏好仍使用 GM 存储。
- 每类候选以随机扰动、少量文字重合、未出现奖励排序；桥接略偏向较大的分量。这是启发式策略，无法保证人类一定认为段落相关。
- 否定过的组合冷却 7 天，跳过的组合冷却 10 分钟。每完成 12 次判断自动打捞新片段；当前候选耗尽后也可手动打捞。大候选池会每轮随机采样孤立片段及分量代表，控制配对计算量。
- 平铺阅读按关联创建顺序展示，每个段落在分量内仅出现一次，所有关系及思考均展示。星图为辅助概览。
- 每 45 秒、窗口恢复焦点，以及提交判断前按 ID 同步。只有成功查询确认缺失才标记删除，断开对应关系。历史关系保留；相同 ID 恢复后接通。删除导致的分裂会重新计算。
- 本地服务原子保存至 `data/graph.json`，保存失败时保留浏览器恢复副本。可导出 JSON。原型按单用户、单窗口使用设计。
- 不向思源写入或修改任何笔记。

```powershell

```

覆盖分量合并、禁止分量内重复配对、隔离、冷却、同步更新、删除断开与恢复，以及单文件构建完整性、Token 排除和备份导入校验。应用层另外覆盖保存失败回退与重试、等待落盘才发布状态、重复与过期提交、同步/导入失败、撤销不覆盖思源最新正文、编辑和移除失败。

## 修改边界与文件导航

- `engine.js`：领域规则，只修改传入的草稿；不接触页面、请求、存储和动画。
- `application.js`：唯一持有真实可变图谱的应用层。提交判断、同步、补充候选、编辑/移除关联、导入及撤销均经过命名用例。外部只能获取分离的快照。
- `io.js` / `server.mjs`：思源与持久化适配。独立版使用 IndexedDB 的完成事件确认保存；开发版等待服务确认原子文件替换。
- `app.js`：装配依赖、保存提示和视图交互。所有写入调用应用用例，界面状态是只读快照；动画只能消费成功结果。
- `motion.js` / `style.css`：视觉反馈与样式，不创建或修改关联。
- `build.mjs`：依次拼装领域、适配、应用、动效与界面，保留文件分区标记，生成单 HTML。

一次判断的顺序是：验证当前配对标识 → 向思源核实 → 在私有草稿中更新关联、思考、计数和隔离状态 → 一次保存完整草稿 → 发布新快照 → 反馈与下一组。失败草稿不发布，也不作为浏览器恢复副本在重载时自动提交。相同配对标识的重复提交不再计数；下一组产生后旧标识失效。所有写操作在同一窗口内排队，避免同步覆盖判断结果。撤销只回退判断产生的字段，保留之后同步的原文、删除状态与新候选。仍以单用户、单窗口为使用边界，尚未实现多个窗口之间的版本冲突协调。
